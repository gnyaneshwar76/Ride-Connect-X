# RideConnectX UI Specification 

## Screen 01 – Splash Screen 

### Purpose 

The Splash Screen serves as the application's entry point. It establishes the RideConnectX brand identity while the application initializes required services, restores the previous session, loads local preferences, and determines the appropriate navigation path. Users cannot interact with this screen. 

--- 

### All UI Components 

- RCX Logo 

- RideConnectX wordmark 

- Smart Navigation tagline 

- Premium dark gradient background 

- Blue ambient glow 

- Animated route/light effect 

- Version label (bottom) 

- Invisible loading state 

--- 

# ### Spacing and Layout 

- Full-screen layout. 

- Logo centered both horizontally and vertically. 

- Wordmark positioned approximately 16dp below the logo. 

- Tagline placed 8dp below the wordmark. 

- Version text aligned at the bottom center with 24dp bottom padding. 

- Safe-area support for all modern Android devices. 

- Background occupies the full display. 

--- 

### Buttons 

None. 

The screen is non-interactive. 

--- 

### Icons 

* RCX application logo 

--- 

### Navigation Flow 

``` 

Application Launch 

│ ▼ 

Splash Screen 

│ 

├── First Launch → Welcome Screen 

│ 

├── Logged In → Dashboard 

│ 

└── Guest Session → Dashboard 

``` 

--- 

### Animations 

- RCX logo fades in. 

- Blue glow gradually expands. 

- Wordmark fades into view. 

- Entire screen cross-fades into the next destination. 

- Total animation duration approximately 1.5–2 seconds. 

--- 

### Expected Behaviour 

- Display branding immediately. 

- Load DataStore preferences. 

- Restore Google session if available. 

- Restore Guest session if available. 

- Initialize BLE service. 

- Initialize notification manager. 

- Determine whether onboarding has already been completed. 

- Navigate automatically without user interaction. 

--- 

# ### Validation Rules 

- Navigation must occur only after initialization completes. 

- If initialization fails, navigate to Welcome Screen as a safe fallback. 

- Prevent duplicate navigation. 

--- 

# ### Backend Hooks 

Required backend components: 

- AppInitializer 

- SessionManager 

- NavigationManager 

- BLEManager 

- SettingsRepository 

- UserRepository 

--- 

### DataStore Usage 

Read: 

- onboardingCompleted 

- guestMode 

- theme 

- selectedVehicle 

- selectedColour 

- fontSize 

- notificationPreference 

Write: 

- lastLaunchTime 

--- 

### Room Usage 

None. 

--- 

### BLE Usage 

- Initialize Bluetooth manager. 

- Check Bluetooth availability. 

- Do not scan yet. 

--- 

### Google Sign-In Usage 

- Restore existing Google account if available. 

- Validate stored session. 

- Do not display account picker.
